# Code review, v2.1 → v2.2

Scope: `src/gradfusion/` (1,900 lines), `scripts/run_gradfusion.py`, `scripts/plus2.py`
and the tests. What I checked first: **the code must keep reproducing the committed
results.** Every table in this repository comes from fixed seeds, so a change to the
default numerical path, even a rounding-level one, would mean the code no longer
reproduces its own results. Every default-path change below was checked to be
bit-identical (see "Verification").

## 1. Review of v2.1

The code is in good shape for research code. The modules are small and each has one job, the
docstrings explain *why*, and the TVDiag-fidelity notes are careful. The problems are about
robustness and duplication, plus one real performance limit.

| # | Where | Problem | Severity |
|---|---|---|---|
| 1 | `losses.supcon_per_sample` | The cosine matrix is computed by broadcasting `F.cosine_similarity` over an (n, n, d) tensor. Forward and backward both materialise n²d floats: 13 MB per term on GAIA (n = 320) and 134 MB at n = 1024. **About 70% of training time** (profiled: `mul`/`div`/`neg` kernels inside `DivBackward`). | Performance |
| 2 | `train.align_weights` + `task_oriented_loss` | GradFusion-DL computes all six SupCon terms to measure gradient alignment, then `task_oriented_loss` computes the same six again from the same inputs. That is 12 SupCon forward passes per step where 6 would do. | Performance |
| 3 | `config.get` | Any keyword is accepted. The code reads ~55 options through `cfg.get(key, default)`, so a misspelt option (`awl_learnabel=True`) is silently ignored and the run trains the wrong model with no error. | Correctness risk |
| 4 | `data.load` | Dataset checks use `assert`, which `python -O` removes. | Robustness |
| 5 | `data.load`, `alerts.py` | Files are opened with `json.load(open(...))` and never closed, which leaks handles and raises `ResourceWarning`. | Robustness |
| 6 | `alerts.alert_bags` | All three raw alert files are parsed twice: once in `vocabulary()`, once again for counting. | Performance (minor) |
| 7 | `alerts.with_alert_bag` | Caches by setting undeclared attributes (`_with_bag`, `bag_vocab`) on a dataclass. Easy to break, and invisible to readers and type checkers. | Maintainability |
| 8 | `evaluate.py` vs `scripts/plus2.py` | The FTI metric (TVDiag's F1) and the ranking metrics are implemented twice, once for models and once for score arrays. | Duplication |
| 9 | `scripts/run_gradfusion.py` | The main entry point imports its recipe (`MEMBERS`, `PLUS`, `metrics`) from the experiment script `plus2.py`, through `sys.path` edits. | Structure |
| 10 | `evaluate.evaluate` | MRR@3 is accumulated in float32, so it is off by ~1e-8 against the float64 value from the score-based path. Seen as 147 mismatches when the stored runs are re-scored. | Correctness (cosmetic) |
| 11 | `train.train` | `w_trace` appends the 3×2 matrix at every step, but only the last one is used. | Memory (minor) |
| 12 | `train.train`, `evaluate`, `ensemble.predict` | An empty training split gives `ZeroDivisionError` deep in the loop. An empty test set does the same in `evaluate`, and an empty model list does the same in `predict`. | Edge cases |
| 13 | `train.align_weights`, `compute_terms` | Tensors are created on the CPU next to tensors on the model's device, so this would fail on a GPU. | Portability |
| 14 | `augment.drop_non_root` | Python loop that writes one element at a time and calls `int(root[b])` per row. | Style (minor) |

**Already optimal, left alone.** Several parts were already right and needed no change:
- The dense batched GraphSAGE: N ≤ 21, so it beats DGL.
- The degree-bucketed LSTM aggregator.
- The masked max-pool.
- The AUG masks.
- The ensemble's averaging of softmax outputs.
- The per-modality gradient grouping in `align_weights`, which takes one `autograd.grad` per task, not per term.

## 2. What changed (v2.2)

| # | Fix | Bit-identical? |
|---|---|---|
| 1 | `losses.pairwise_cosine(emb, fast)`. With `fast=True` (config `fast_supcon`, CLI `--fast`), cosine = `z @ z.T` of the normalised rows: one GEMM and O(n²) memory. **Off by default.** | Default path: yes. Fast path: no (see §6). |
| 2 | `align_weights` stores its six terms in a dict and `task_oriented_loss` reuses them. Reuse happens only when the terms were built with the same options (none of the §6.13 pair weightings active). | Yes, same tensors |
| 3 | `config.OPTIONS`: the list of every option the code reads. `config.get` raises `KeyError` for any other name. The list was generated by searching the code, and a test keeps the presets valid. | Yes |
| 4 | `assert` → `_check(...)`, which raises `ValueError`. Also new: "no usable incidents" is now an error. | Yes |
| 5 | `read_json` / `_read_pickle` helpers that use `with`, plus a comment on pickle trust. | Yes |
| 6 | The raw alerts are read once and passed to `vocabulary(ds, raw)`. The regex is compiled once, and GAIA skips it. | Yes |
| 7 | `Dataset.bag_vocab` and `Dataset._with_bag` are now declared fields. `_with_bag` is `init=False`, so `dataclasses.replace` drops it. | Yes |
| 8 | `evaluate.fti_metrics` and `evaluate.metrics_from_scores` are shared. `plus2.metrics` is now an alias for `metrics_from_scores`, and `per_class` reuses `_ranks`. | Yes (re-scored all 204 stored runs) |
| 9 | The recipe now lives in the package: `config.GRADFUSION`, `config.GRADFUSION_ARM` and `config.MEMBER_SEED_OFFSETS`. `run_gradfusion.py` imports nothing from `plus2.py`, gains `--fast` and `--threads`, and still works without `pip install`. | Yes |
| 10 | MRR@3 is accumulated in float64. | Changes MRR@3 in the 8th decimal only |
| 11 | Only the last weight matrix is kept, as a copy. Note: `v5_align`'s `w` is a *view of a buffer*, which `load_state_dict` overwrites when the best epoch is restored. Keeping a reference instead of a copy would therefore have reported the best epoch's matrix, not the last one. | Yes |
| 12 | Clear `ValueError`s for an empty training split, `epochs < 1` / `batch_size < 1`, an empty `evaluate` set and an empty model list. | Yes |
| 13 | `cos` and `zero` are created on the model's device. | Yes |
| 14 | `keep[b, picks] = False` in one indexed write, over `root.tolist()`. The order of random draws is unchanged. | Yes |

## 3. Complexity

The terms used in the table:
- n = graphs per step (2 × batch size, after AUG);
- d = 32, the embedding width;
- N = instances (10–21);
- M = incidents;
- E = edges.

| Operation | Before | After |
|---|---|---|
| One SupCon term, time | Θ(n²d) elementwise (broadcast), forward + backward | Default: same. Fast: Θ(n²d) as one GEMM |
| One SupCon term, extra memory | Θ(n²d) (forward and saved for backward) | Default: same. Fast: **Θ(n²)** |
| SupCon forward passes per GradFusion-DL step | 12 | **6** |
| Autograd passes per GradFusion-DL step | 9 (2 task + 6 term + 1 loss) | 9 (needed by the method) |
| `data.load` adjacency | Θ(E) Python loop | Θ(E) vectorised |
| `alert_bags` JSON parsing | 2 × every raw file | 1 × |
| `w_trace` memory | Θ(steps) | Θ(1) |
| `config.get` | Θ(k) | Θ(k) (one set difference) |

**Measured (1 CPU thread).**
- *Default path:* the wall time did not change. Hotel GradFusion+ ran 132 s before and 136 s after; Sock Shop ran 390 s before and 405 s after, both while two jobs shared the 2 cores. The saved SupCon forwards are small next to the backward passes, which are unchanged, so fix 2 is a clean-up, not a speed-up.
- *Fast mode:* the SupCon term alone is 30× faster at n = 256 (74 → 2.5 ms, forward + backward) and 40× faster at n = 1024 (1,625 → 42 ms). End to end, one GradFusion+ member trains about 2–2.5× faster: Hotel seed 5 took 42 s against 91 s.

## 4. Why these changes

- **Typo-proof config (3)** is the most valuable fix for a research codebase. A silently ignored option produces a wrong result that looks valid, which is the worst kind of bug in an experiment. A frozen allowlist catches it in one line and changes nothing else.
- **Opt-in fast mode (1).** The exact path is part of the contract ("runs are deterministic by seed"), so the faster path is a choice the user makes, not a silent change.
- **One metric implementation (8).** Before this, the FTI F1 (an unusual definition, the harmonic mean of weighted P and R) existed in two places that could drift apart. Now it exists once, and the old name still works for `make_plus2_report.py`.
- **The recipe in the package (9).** A user's entry point should not depend on an experiment script's internals.
- **`ValueError` instead of `assert` (4, 12)** gives checks that survive `-O` and errors that name the cause.

## 5. Tests

18 new tests in `tests/test_robustness.py` (36 → 54), plus one slow end-to-end test.

| Kind | Test |
|---|---|
| Normal | Fast cosine equals the exact one (n = 300). Fast SupCon equals the exact one in value **and gradient** (n = 64, 257). Reusing terms gives a bit-identical loss. Adjacency matches `edges.json`. Alert bag is cached and idempotent. A hand-worked metric example (HR@k, MRR@3, F1). |
| Boundary | Node drop with N = 1 (nothing can be dropped), pct = 0, pct = 1 (all but the root), and the real Hotel and Sock Shop settings. SupCon with n = 2. An all-zero embedding (cosine 0 on both paths). A tie in scores, broken by instance index. |
| Edge / invalid | A misspelt option raises `KeyError`, while `None` still means "keep". Every preset (FIDELITY, PAPER, GRADFUSION) is accepted. A strict-load mismatch raises `ValueError`, not `AssertionError`. An empty training split, an empty `evaluate` set and an empty model list each raise `ValueError`. |
| End to end | `GRADFUSION_SLOW=1 pytest`: one GradFusion+ member on Hotel seed 5 gives HR@1 0.833 and F1 0.821, the committed numbers. |

**Verification beyond the unit tests.**
- *Bit-identity.* Three full training runs were done with the v2.1 and the v2.2 code, and the SHA-256 of the final weights matched in every case: Hotel GradFusion+ (seed 5), Hotel TVDiag (seed 5) and Sock Shop GradFusion+ (seed 7). HR@1, F1, macro-F1, the epoch count and the learned weight matrix were equal too.
- *Data.* `data.load` and `with_alert_bag` return tensors equal to v2.1's for all three datasets.
- *Metrics.* All 204 stored runs were re-scored with the shared metric code and match the stored JSON. The only mismatches are float32 MRR, which is fix 10.

**Fast mode against the committed results.** Full GradFusion (three members) with
`fast_supcon=True` on the ten seeds behind the results table (5–9, 30–34), compared with the
committed exact runs, paired by seed (`results/fast_supcon/runs.json`):

| Dataset | HR@1 exact → fast | Δ (p) | F1 exact → fast | Δ (p) | Training, exact → fast |
|---|---|---|---|---|---|
| A · GAIA | 0.767 → 0.767 | +0.001 (0.39) | 0.948 → 0.948 | +0.000 (0.41) | 6.3 → 1.2 min (5.4×) |
| C · Sock Shop | 0.871 → 0.872 | +0.001 (0.85) | 0.648 → 0.644 | −0.004 (0.50) | 18.1 → 6.6 min (2.7×) |
| D · Hotel | 0.841 → 0.837 | −0.004 (0.19) | 0.860 → 0.859 | −0.001 (0.70) | 5.5 → 2.2 min (2.5×) |

No difference is significant (paired t-test, before any multiple-testing correction) and
every one is within ±0.004, far below the seed-to-seed spread. Training times are total
member time per GradFusion run, one thread each, two jobs sharing two cores in both cases.

## 6. Trade-offs, and what I did not change

- **Fast mode is not bit-identical.** The matrix product sums in a different order, which gives about 1e-7 relative error per term. Over hundreds of epochs with early stopping, that can change which epoch is kept and so a run's numbers. Use it for development and new experiments, and keep the default to reproduce the tables. The table above shows the change is within seed noise.
- **The configuration stays a plain `dict`.** A typed, frozen dataclass would be cleaner, but every module, script and test reads `cfg` as a dict. The allowlist gives most of the safety (no silent typos) at a small fraction of the change.
- **The research switches stay in.** About half of `model.py` and `train.py` is off-by-default options from the research log (LSTM/attention aggregators, curriculum, oracle weights, and others). Removing them would make GradFusion's own path much shorter, but `results/` and the HISTORY refer to them, and the existing tests cover them. For a paper-only release, a branch that deletes them is the right next step; it should be done as its own change.
- **Ranking ties.** `evaluate` breaks ties with `torch.argsort`, while `metrics_from_scores` uses a stable NumPy sort. They differ only for exactly equal logits, which never occurred in the stored runs. Unifying them could change committed numbers in principle, so they were left as they are.
- **CPU only.** The device fixes stop the weighting code from mixing devices, but datasets are never moved to a GPU. Full GPU support is a feature, not a fix, and the method trains in minutes on one core.
- **`pickle`.** The data loader unpickles TVDiag's released files. These are checked against `data/SHA256SUMS`, but they should never be replaced with files from an untrusted source.
